# 地点化媒体采集与归档方案

版本：1.1（2026-11-13）

## 1. 目标与边界

本方案把“武汉东湖”拆成可人工核验的小地理单元，以地点别名和水生植被物候词组合检索公开媒体。最终素材库只接收图片和视频，不接收纯文本帖子，也不保存作者身份和正文。

研究时段为 2018-01-01 至 2026-10-30。发布时间超出范围的结果不进入最终素材库；发布时间未知的地图相册可用于空间核对，但不能作为物候日期证据。

## 2. 平台适配

| 平台 | 采集入口 | 媒体归档 | 说明 |
|---|---|---|---|
| 小红书 | MediaCrawler `xhs` | 自动 | 图片、视频；需要登录 |
| 抖音 | MediaCrawler `dy` | 自动 | 封面、图集、视频；需要登录 |
| 快手 | MediaCrawler `ks` | 自动 | 封面、视频；需要登录 |
| 微博 | MediaCrawler `wb` | 自动 | 图片、视频；需要登录 |
| 哔哩哔哩 | MediaCrawler `bili` | 自动 | 封面、视频；需要登录 |
| 百度地图 | 独立地点相册清单 | 自动整理 | MediaCrawler 不支持；时间缺失时保持未知 |
| 高德地图 | 独立评价/相册清单 | 自动整理 | MediaCrawler 不支持；保留 POI，禁止把 POI 当拍摄机位 |
| 大众点评 | 登录浏览器 + 通用清单 | 自动整理 | 不直接集成代理池或验证码规避方案 |
| 美团 | 登录浏览器 + 通用清单 | 自动整理 | 开源项目以商家/商品为主，媒体内容采用浏览器辅助采集 |
| 两步路 | 附近图片/轨迹 + 通用清单 | 自动整理 | 无可靠专用媒体采集器，保留轨迹/时间/画面证据 |

平台路由的单一配置为 `config/platform_sources.json`。专用适配器调研见 `docs/platform_adapter_research.md`。

## 3. 空间单元

`config/east_lake_spatial_units.csv` 当前定义 14 个单元，包括用户截图中的 10 个重点岸段，并补充马鞍山森林公园、武汉植物园、渔光景区和喻家山。每个单元包含：

- 稳定 `unit_id`；
- 区域和归档地点名；
- 景点、湖名、桥、栈道、驿站等别名；
- 截图编号和范围说明；
- 优先级。

`EL09 水生所—官桥湖岸段` 位于研究边界附近，必须人工复核后再并入东湖结论。

## 4. 关键词矩阵

`config/aquatic_media_terms.json` 将词汇分为八类：

1. 植物：荷花、荷叶、残荷、睡莲、水草、浮萍、水葫芦、芦苇、菖蒲、香蒲等；
2. 物候：返青、萌芽、展叶、初花、盛花、末花、枯黄、衰败、越冬等；
3. 空间：池塘、湖湾、浅滩、岸边、湿地、水道、栈道等；
4. 观察活动：航拍、延时、骑行、划船、游船、钓鱼等；
5. 管理事件：打捞、清理、收割、泛滥、爆发、覆盖水面等。
6. 春季补采：早春、春节、元宵、春游、踏青、清明、春分、谷雨、三月、四月、五月、新绿、雨后等；
7. 中性活动：周末、散步、骑行、观鸟、露营、遛娃、晨跑、游园、CityWalk、Vlog、航拍等；
8. 四季平衡：春、夏、秋、冬及季节景色，用发布时间月份分池，不从季节词反推拍摄日期。

关键词生成顺序为“地点原名 → 春季补采 → 四季平衡 → 节气/节假日 → 中性活动 → 场景/物候”。这可避免荷花、残荷等高相关词把结果过度推向 6 月以后。季节补采批次允许文案不含水生植被词，先保留公开图片/视频，再通过 OCR、画面和人工核验判定研究价值。

计划同时生成一级地标检索和“武汉/东湖 + 场景词”的无定位召回检索，例如：

- `东湖荷园 荷花 盛花`
- `筲箕湖 水草 航拍`
- `落雁景区 湿地公园 栈道`
- `后湖 浮萍 打捞`
- `白马景区 水葫芦 泛滥`

无定位召回的目的，是找到正文、字幕或画面文字指向东湖、但平台没有挂载 POI 的内容。检索词本身不能作为位置证据。

## 5. 生成计划

```bash
python3 src/build_media_collection_plan.py
```

生成文件为 `data/interim/media_collection_plan.json`，包括 9 个一级地标任务、1 个无定位区域召回任务、平台路由、研究时段和低频策略。该文件属于本地运行状态，不进入 GitHub。

先查看任务，不采集：

```bash
python3 scripts/run_place_media_collection.py \
  --unit-id BP05 \
  --platform dy \
  --keyword-count 1 \
  --max-notes 10
```

确认地点与关键词后执行：

```bash
python3 scripts/run_place_media_collection.py \
  --unit-id BP05 \
  --platform dy \
  --keyword-count 1 \
  --max-notes 10 \
  --execute
```

不同批次使用 `--keyword-start` 续跑。平台搜索接口可能按整页返回，所以 `--max-notes` 是上限目标，不保证小于页面最小批量。

按月份补采示例：

```bash
python3 scripts/run_place_media_collection.py \
  --unit-id BP01 \
  --platform xhs \
  --strategy spring_backfill \
  --keyword-start 0 \
  --keyword-count 1 \
  --target-months 1-5 \
  --max-notes 10 \
  --execute
```

`spring_backfill`、`calendar_event`、`neutral_activity` 和 `seasonal_balance` 会自动启用“媒体后筛”，并将目标月份传给归档器。发布时间未知或不在目标月份的内容不计入该补采批次。

## 6. 归档结构和命名

`media_collected/` 保留平台采集后的原始可追溯结构；当前人工检查目录通过下列命令生成：

```bash
python3 src/rebuild_poi_media_archive.py --project-root .
python3 src/import_poi_archive_to_posts.py --project-root .
```

当前目录：

```text
media_by_landmark_year/
└── 东湖磨山景区/
    ├── 2025/
    │   ├── 东湖磨山景区-20250605-155203-小红书-001.webp
    │   └── 媒体索引.csv
    ├── 2026/
    └── 年份未知/
```

平台细碎 POI 先映射到 `config/east_lake_poi_hierarchy.csv` 中的 9 个一级地标；只有东湖整体证据的记录进入“东湖风景区（综合）”。每个地标再按发布年份分层，未知年份单独存放。文件名为“一级地标-发布时间-中文平台名-三位序号”，序号在每个“地标 × 年份”目录内独立编号。

`_归档索引.csv` 和年度目录中的 `媒体索引.csv` 保存新旧路径、SHA-256、平台、原空间单元、一级地标、年份、内容 ID、媒体序号、媒体类型、采集/发布时间、检索词和来源链接。不保存昵称、账号 ID 或评论。

默认使用硬链接，不能硬链接时才复制；原始媒体不会移动或删除。平台原始 POI 仍在处理表和地图详情中保留，一级地标只用于目录和地图聚合。

大于 50 个文件的图集不会擅自丢弃，但会标记为 `large_gallery_review`，供人工抽查首、中、末图。没有本地媒体的纯文本记录直接跳过。

正式归档还要依次通过三道门槛：研究时段、本地媒体存在、水生植被/湿地语义。地点可以来自平台 POI、正文、OCR 或人工画面地标；只有检索词、没有独立位置证据的记录留在候选区，不进入具体一级地标。

## 7. 归档既有数据

```bash
python3 src/archive_existing_media.py --project-root .
```

程序先使用原空间单元映射一级地标；旧记录缺少空间单元时，再使用平台 POI、地址和检索词做最长别名匹配。无法唯一匹配时归入“东湖风景区（综合）”，不会猜测到更具体的景点。

## 8. 质量控制

- SHA-256 去重，避免重复下载造成重复计数；
- 图片/视频扩展名白名单；
- 只归档实际存在的媒体文件；
- 平台位置、正文、OCR、人工画面地标分列保存；
- 检索词不参与位置证据评分；
- 研究时段硬过滤；
- 所有检索词包含“武汉”锚点，减少其他城市同名“东湖”；
- 必须命中当前空间单元的具体 POI，多个单元同强度命中时拒绝自动分配；
- 必须命中水生植被、湿地或水域管理语义；
- 大图集标记抽查，不按文件数量直接认定为异常；
- 地点只按显式 POI/别名匹配，宽泛“东湖”进入待核验目录；
- 百度地点相册无发布时间时不得填入采集时间；
- 平台 POI 与画面位置分别标注。

## 9. 合规与停止条件

- 只访问公开可见内容，使用用户自己的正常登录会话；
- 并发固定为 1，不启用代理池，不抓评论；
- 遇到验证码、访问限制、账号风险提示或平台禁止自动访问时立即停止；
- 不绕过验证码、签名、权限或付费限制；
- MediaCrawler 的许可证限定非商业学习研究，并明确反对大规模、干扰性采集；因此“没有条数限制”在本项目中解释为持续增量采样，不解释为无限并发或无边界抓取；
- 原始媒体仅限内部研究和人工核验，GitHub 只发布代码、配置与文档。

误分文件不直接删除，可使用 `src/quarantine_archive_batch.py` 将指定采集批次或内容 ID 移入 `media_quarantine/`，同时从正式清单移除，保留恢复可能。
